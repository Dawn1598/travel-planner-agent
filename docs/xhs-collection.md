# 小红书采集：日期核实、质量审核与新增目标

## 根因排查

2026-10-25 检查本地已有 40 篇笔记，其中 28 篇 `published_at` 为空。没有将这些日期补成采集时间，也没有删除历史记录。

旧代码的具体原因：

1. `note_from_data()` 只要求正文超过 25 字，即使解析不到日期也返回笔记。
2. 详情循环因此设置 `found=True`，而可见页面日期提取在 `if not found` 内；“正文成功、日期缺失”会跳过补读。
3. 仅检查 `time/publishTime/publish_time` 顶层字段，没有处理详情响应、`noteDetailMap[id].note` 及发布元数据内的嵌套字段。
4. `walk_notes()` 遍历所有笔记却没有限定目标 ID，推荐内容可能混入结果。
5. 日期字符串的时刻和时区被丢弃；相对日期没有记录观测锚点、原文和解析依据。
6. `save_notes()` 接受空日期，并把未变化的重复笔记也计入成功。爬虫只读首屏前几条链接，失败会占掉这些访问槽。

## 调用链与职责

```text
Agent.get_travel_info
  → 本地 RAG：近期 → 更早，模型检查当前问题的相关性/充分性
  → 不足时 crawler.crawl
      → XhsBrowser：正常登录、可见排序、响应/状态/DOM
      → xhs_pipeline：收集、ID 去重、刷新跳过、重试、预算、排序
      → xhs_extract：ID 对应关系、类型过滤、日期解析、字段校验
      → knowledge.judge_notes：每批最多 5 篇判断知识库价值
      → knowledge.save_notes：再次校验，返回实际新增/更新/未变结果
  → 重新检索并判断是否回答当前问题
```

Agent 决定查询主题和方向，不逐篇控制浏览器。入库审核不接收当前问题；有旅行价值的资料不会因为当前问题用不上而被排除。420 字分块、长段 60 字重叠保持不变。

## 候选与时间排序

用可见“综合/筛选 → 最新”控件切换排序，等待搜索响应，检查选中态或关联请求中的排序参数。失败时记录原因，后续仍使用核实日期本地排序。

滚动读取卡片和正常浏览器响应。相同 24 位笔记 ID 的不同 URL 参数只算一个候选；达到上限、平台无更多结果、连续无新增或预算耗尽后停止。候选尽可能保存标题、摘要、链接、类型和日期。

候选已确定为图文的直接排除。已合格入库且在刷新周期内的记录跳过详情；缺日期或未经审核的旧记录不能因此跳过补验。

其余候选进入详情核实日期，并缓存完整文字。详情日期优先于搜索摘要中的日期；正文得到后仍会补读日期。缓存用于后续送审，不再次打开相同详情。核实后的候选按真实发布时间降序，时间相同时用 ID 保持稳定次序，ID 不参与日期推测。

`verification_attempts_complete` 只表示已尝试所有待核实候选；`verification_complete` 还要求没有日期/读取失败或未核实候选。图文排除和刷新跳过另计。报告给出总候选数、待核实范围、尝试数与成功数，不会声称“已选出全部候选中最新的 30 篇”。

## 发布时间是硬门槛

优先级：详情响应 → 页面初始状态 → 已绑定当前 ID 的详情 DOM → 搜索响应中明确的发布时间。

支持 `noteId/note_id/id` 的显式绑定，以及 `noteDetailMap[目标ID]` 的键绑定。仅在匹配笔记对象内沿嵌套字段读取发布元数据，遇到其他笔记 ID 不继承绑定；排除用户、评论、推荐、图片、视频等无关分支。泛化 `time` 仅允许在笔记对象或发布元数据中使用。

可见日期必须绑定详情根节点 ID、当前笔记 ID 或 canonical URL，且当前页面 URL 与目标 ID 一致。不会取整页任意日期、评论日期或其他笔记日期。

每个有效日期保存 `source/path/note_id/raw/observed_at/basis`。失败保存分类、原值、尝试次数和检查过的字段路径。不会保存 Cookie、Authorization 或完整浏览器响应；调试日志和持久化诊断会脱敏。

| 输入 | 处理 |
|---|---|
| Unix 秒/毫秒 | 区分单位，转为带时区时间并校验范围 |
| ISO 8601、Z、时区偏移 | 保留实际时刻 |
| 年月日及本地时刻 | 无偏移时明确按 Asia/Shanghai 解析 |
| 仅完整年月日 | 本地零点存储，注明 day_precision，不假装有精确时刻 |
| N 秒/分钟/小时/天/周前、刚刚 | 以观测时刻解析，记录原文与锚点 |
| 今天/昨天/前天，可含时刻 | 上海日历日；无时刻按日精度记录 |
| 10-12 等无年份日期 | unknown_year，不猜年份 |
| 编辑、修改、更新时间 | edited_time，排除 |
| 缺失、非法、未来、其他 ID 日期 | 分类失败，有限重试后跳过 |

入库再次用原值和观测锚点解析，必须与 `published_at` 一致。采集时间、ID 推测值、模型生成值不能通过这个门槛。标题、完整文字正文、ID、有效来源链接与发布时间均必填，不用正文截取值伪造缺失标题。

## 图文排除与模型质量判断

平台 `normal/image/images/image_text/图文` 均排除；未知类型带图片列表也排除。正文明确依赖“路线见图、长图攻略、截图攻略”等内容时排除。未知类型补取后仍无法识别的笔记不入库。`video` 只表示平台类型，本项目只判断其独立完整的文字，不下载或解析视频。

浏览器阻止 image/media 请求并禁用 service worker。不读取图片像素，不调用视觉模型，不做 OCR。严格排除图文后，搜索结果可能大部分或全部不可用，实际新增可以为零。

每批最多 5 篇提供标题、完整正文和已核实元数据，正文不截断。模型拒绝明显广告、堆砌、残缺，以及核心信息依赖图片/视频的内容；提取正文明确出现的城市、地点和主题，不确定时留空，不使用查询城市替代。笔记作为待分析文本，不能指挥模型或补写事实。

```json
{"notes":[{"note_id":"...","accept":true,"cities":["杭州"],"places":["西湖"],"topics":["步行路线"],"reason":"有路线与时间建议"}]}
```

缺失、重复 ID、额外 ID 或格式失败的结果不能直接入库。最终须同时满足程序校验和对应 ID 的质量通过结果。

`Note` 增加 `content_type/date_provenance/quality/cities/places/topics`；`city` 兼容字段由提取的城市列表构成。旧记录保留，未核实日期或未通过质量审核的记录暂不参与 RAG，重新采集通过后恢复。

`save_notes()` 返回逐 ID 的 `new/updated/unchanged/rejected/failed/time_budget`。只有数据库实际创建的新笔记计入目标。正文未变且已有对应模型向量时，不重新向量化；可以补齐或修正标题、已核实日期等元数据。标题单独修正时保留原向量，下次正文更新才重建“标题 + 分块”向量。

## 配置与预算

| 配置 | 默认 | 说明 |
|---|---:|---|
| XHS_CANDIDATE_LIMIT | 200 | 唯一候选数，运行时最多允许 200 |
| XHS_TARGET_NEW | 30 | 合格新笔记目标 |
| XHS_MAX_VISITS | 240 | 详情导航次数，包含重试 |
| XHS_TIME_BUDGET_SECONDS | 600 | 整轮预算：启动、搜索、详情、模型、索引 |
| XHS_RETRIES | 1 | 每篇首次读取之外的重试次数 |
| XHS_STAGNANT_ROUNDS | 3 | 连续无新增的滚动停止阈值 |
| XHS_REFRESH_HOURS | 24 | 合格记录刷新周期，0 表示不跳过 |

旧 `XHS_MAX_NOTES` 不再使用。浏览器等待上限取操作上限与剩余预算的较小值，质量模型使用剩余预算的异步超时。日期核实预留至多 60 秒（预算的 20%）给送审与入库，未核实完会明确报告。

预算耗尽不启动新访问、送审或索引。已开始的同步本地向量计算和资源释放无法中途强杀，单次计算可能让墙钟时间略超预算；计算后再检查，超时不写入该条。首次模型下载也有此限制，生产环境应提前准备缓存。这不是强杀所有操作的硬实时截止。

搜索页、详情页响应缓冲独立，详情读取串行。登录失效、安全验证或访问限制立即停止，沿用现有登录恢复流程。context/browser/锁在异常时释放，清理异常不覆盖原来的登录异常。

## 进度与诊断

页面显示候选数、日期核实范围、送审、新增进度和停止原因。正常 Agent/RAG 路径将完整报告保存到 `CrawlLog.report`，关闭调试也保留；`get_travel_info` 返回不含逐篇明细的 `crawl_report` 给 Agent。

报告包含 `candidate_count/verification_eligible/verification_attempted/date_verified/verification_complete/new/updated/unchanged/shortfall/visits/elapsed_seconds/stop_reason/counts/items`。逐篇区分排除、刷新跳过、读取失败、日期失败、质量拒绝与实际新增。预算未处理的候选标为 unverified；达到目标后未送审的缓存候选仍标为 date_verified，不计入新增。

来源链接入库时去掉访问参数，保留 canonical URL；使用时仍可能需要登录。完整报告按笔记逐条脱敏，不受调试日志单条最多 100 项的显示截断影响。保留原有同查询、同城市 10 分钟冷却，登录失败不阻止完成登录后立即恢复。
